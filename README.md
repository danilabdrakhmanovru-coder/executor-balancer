# Executor Balancer (.NET)

Сервис распределения заявок между исполнителями в реальном времени.
Готово: ядро и интеграция с АИС, конструктор правил и весов, аналитика со справедливостью распределения,
пробная проверка заявки, журнал изменений, выгрузка в Excel, генератор нагрузки.

Стек: .NET 10, ASP.NET Core Minimal API, EF Core + PostgreSQL, Redis (атомарный выбор), xUnit, Python для нагрузки.

## Структура

```
src/ExecutorBalancer.Domain          сущности и перечисления

tests/ExecutorBalancer.Tests         модульные тесты и тесты конкурентности
tools/loadgen.py                     генератор нагрузки: многопоточная подача заявок и смена статусов

docs/DECISIONS.md                    трактовки ТЗ и принятые решения

```

## Запуск (Windows PowerShell)

Сайт в интернете (сервер Yandex Cloud, HTTPS, YandexGPT Pro) — пошагово в [docs/DEPLOY.md](docs/DEPLOY.md).

1. Секреты — одной командой, файл `.env` создаётся со случайными значениями:

```powershell
function New-Secret { -join ((48..57)+(65..90)+(97..122) | Get-Random -Count 32 | % {[char]$_}) }
@"
POSTGRES_PASSWORD=$(New-Secret)
REDIS_PASSWORD=$(New-Secret)
INTEGRATION_API_KEY=$(New-Secret)
AIS_API_KEY=$(New-Secret)
ADMIN_PASSWORD=$(New-Secret)
SWAGGER_ENABLED=true
COMPOSE_PROFILES=demo
DEMO_ENABLED=true
"@ | Set-Content -Encoding ascii .env
Get-Content .env
```

`ADMIN_PASSWORD` — пароль встроенного администратора (логин `admin`). Остальных пользователей с ролями
заводит администратор в «Настройки → Пользователи».

2. Сборка и тесты: `dotnet build` и `dotnet test`.
3. Запуск: `docker compose up -d --build` (с `.env` выше — в демо-режиме, см. «Демонстрация и боевой запуск»).

| Адрес | Что |
|---|---|
| http://127.0.0.1:8080 | интерфейс (логин `admin`, пароль `ADMIN_PASSWORD`) |
| http://127.0.0.1:8080/swagger | описание API балансировщика |
| http://127.0.0.1:8081 | эмулятор АИС (API, ключ `AIS_API_KEY`) — только в демо-режиме |

4. Нагрузка (Python 3, без установки пакетов):

```powershell
python tools/loadgen.py --setup                      # завести 15 исполнителей
python tools/loadgen.py --rate 4000 --duration 300   # 4000 заявок/ч, 5 минут
python tools/loadgen.py --rate 20000 --duration 60   # пик
python tools/loadgen.py --rate 4000 --chaos          # исполнитель «уходит» в середине прогона
```

Путь заявки: генератор → эмулятор АИС → балансировщик (выбор за миллисекунды) →
доставка назначения обратно в АИС → запись в АИС через 2–10 с.

## Интерфейс (http://127.0.0.1:8080)

Сервис работает с несколькими **отделами** одновременно — например, «Банк», «Колл-центр», «Логистика»,
«Интернет-магазин» (создаются при первом запуске, по одному на каждый шаблон сферы). У каждого отдела свои
параметры и правила, сотрудники, заявки и отчёты. Отдел выбирается в шапке; переключение ничего не стирает.

Меню — пять разделов, внутри раздела — подменю: **Главная** («Как это работает»: путь заявки и чек-лист готовности),
**Работа** (Мониторинг, Заявки, Сотрудники), **Анализ** (Аналитика, Разбор заявок), **Настройки** (Параметры и
правила, Проверка заявки, Рейтинг и сверхнорма, Отделы, Пользователи, Журнал) и, только в демо-режиме,
**Тестовый стенд**. Раздел открывается на вкладке, где были в прошлый раз; вкладки, недоступные роли, не показываются.
Заявки создаёт не пользователь сайта, а клиент во внешней системе (АИС); на демонстрации её заменяет «Тестовый стенд».

| Раздел → вкладка | Что можно сделать |
|---|---|
| Главная → Как это работает | путь заявки по шагам с живыми цифрами отдела (щелчок — в нужный раздел), чек-лист «что сделать, чтобы заявки распределялись», кто участвует |
| Работа → Мониторинг | плитки, назначения по минутам, нагрузка сотрудников, лента; щелчок по заявке — почему выбран этот сотрудник |
| Работа → Заявки | все заявки отдела с фильтром (ждут, в работе, на доработке, решены); карточка — путь заявки: поступила, кому и почему назначена, доставлена в АИС, доработки, результат и баллы |
| Работа → Сотрудники | кто на работе, что умеет, сколько получил сегодня, качество за 7 дней; предупреждение о сотрудниках без навыков; режим «больше нормы»; **загрузка из файла** (шаблон отдела для Excel → проверка по строкам → загрузка одним действием); в демо — добавить, отправить на перерыв или изменить навыки через эмулятор АИС |
| Страница сотрудника | щелчок по имени: что умеет (навыки значками и в каких правилах участвуют), норма, качество, место в рейтинге, активность за неделю, последние заявки |
| Анализ → Аналитика | периоды «сегодня / 24 ч / 7 дней / 30 дней»: динамика, отклонение от справедливой доли, **рейтинг сотрудников**, «количество против качества», типы назначений, таблица по сотрудникам, выгрузка в Excel |
| Анализ → Разбор заявок | за сутки: хватает ли сотрудников с нужными навыками по каждому значению параметров заявки, где очередь и доработки, какие правила отсекают заявки от всех; кнопка **«Разобрать с ИИ»** — выводы и советы руководителю по этим цифрам (если подключена модель) |
| Настройки → Параметры и правила | сфера отдела (шаблон), параметры заявки и сотрудника, правила подбора, правила веса — применяются сразу, без перезапуска |
| Настройки → Проверка заявки | ввести параметры и увидеть, кому ушла бы заявка и почему; щелчок по сотруднику — каждое правило: что у заявки, что у него, выполнено ли; ничего не назначает |
| Настройки → Рейтинг и сверхнорма | штрафы за доработку и слишком быстрое закрытие, потолок режима «больше нормы», пороги качества |
| Настройки → Отделы | создать отдел со сферой из шаблона или **своей сферой** (мастер: параметры заявки → параметры сотрудника, правила и веса создаются сами), переименовать, удалить пустой; адрес API отдела для АИС |
| Настройки → Пользователи | пользователи и роли: логин, имя, роль, отделы, блокировка, смена пароля |
| Настройки → Журнал | кто, когда и что поменял в настройках отдела (до и после), входы, пользователи, создание и удаление отделов |
| Тестовый стенд | пульт эмулятора АИС (вместо настоящей АИС) для выбранного отдела: завести сотрудников, запустить поток обращений, отправить обращение вручную; живая схема «путь заявки» |

### Роли

| | Наблюдатель | Руководитель отдела | Администратор |
|---|---|---|---|
| Мониторинг, заявки, сотрудники, аналитика, разбор заявок, проверка заявки | смотрит | смотрит | смотрит |
| Сотрудники: загрузка из файла, режим «больше нормы» | — | да | да |
| Запуск ИИ-разбора, журнал отдела | — | да | да |
| Параметры и правила, рейтинг и сверхнорма | смотрит | смотрит | меняет |
| Отделы, пользователи, входы в журнале, тестовый стенд | — | — | да |
| Какие отделы видит | отмеченные у пользователя (ничего не отмечено — все) | так же | все |

Встроенный администратор `admin` (пароль — `ADMIN_PASSWORD`) есть всегда, в базе не хранится и заблокировать
его нельзя. Остальных пользователей заводит администратор; права проверяет сервер при каждом запросе, чужой отдел
выглядит как несуществующий (404). Блокировка, смена роли, отделов или пароля закрывают открытые сессии за 10 секунд.
Забыл пароль — администратор нажимает «Сбросить пароль» у пользователя: новый случайный пароль показывается ему
один раз (в базе — только хеш), старый перестаёт работать, в журнале — «пароль сменён». Пароль встроенного
`admin` меняется в `.env` (`ADMIN_PASSWORD`) и перезапуском.

## Сценарий демонстрации (всё — кнопками в интерфейсе)

1. Открывается «Как это работает»: путь заявки и чек-лист. В шапке выбрать отдел «Банк», вкладка **«Тестовый стенд»**: «Завести сотрудников» — эмулятор АИС создаёт
   сотрудников отдела со случайными навыками и лимитами.
2. Поток обращений (4000 в час, как в кейсе, или больше) → «Запустить». Схема «путь заявки» и лента оживают;
   щелчок по назначению — почему выбран этот сотрудник. Одно обращение вручную — кому ушло и почему остальные не подошли.
3. Переключиться на «Логистику» и сделать то же самое: теперь параллельно идут два потока, у каждого отдела
   свои сотрудники и правила. Движок один и тот же — меняются только настройки; это и есть универсальность.
4. **«Сотрудники»** → «На перерыв»: его открытые заявки сразу уходят коллегам по отделу.
5. **«Настройки»** → новый параметр (например, язык) и правило — следующие заявки отдела учитывают его без
   перезапуска; генератор тоже начинает заполнять новый параметр. Другие отделы не меняются.
6. **«Настройки → Отделы»** → «Новый отдел» со сферой из шаблона — появляется рядом с остальными.
7. **«Аналитика»** — отклонение от справедливой доли, выгрузка в Excel; **«Журнал»** — все изменения.
8. **Мотивация.** На «Сотрудниках» включить одному «Больше нормы: +30%» — когда у коллег норма набрана,
   излишки уходят ему (тип «сверх нормы»). В «Аналитике» — рейтинг: у «торопливого» сотрудника эмулятора
   много закрытых, но качество ниже порога — он «вне рейтинга» и справа внизу на графике «количество
   против качества».

### Рейтинг и режим «больше нормы» (свои фичи)

- **Балл за заявку = вес × коэффициент качества.** Коэффициент снижается за каждую доработку и за
  подозрительно быстрое закрытие. Место в рейтинге — только при качестве не ниже порога (по умолчанию 80%).
- **«Готов взять больше нормы»:** сотрудник с суточным лимитом берёт до N% сверх — но только излишки:
  заявка уходит ему, лишь когда у всех подходящих коллег норма набрана.
- **Защита от работы на количество:** потолок режима; при качестве ниже порога режим приостанавливается
  сам; сложные заявки сверх нормы — только при подтверждённом высоком качестве.
- **«∞» в «Сегодня / норма»** — у сотрудника нет суточного лимита (кейс это разрешает). Заявки от
  родительской идут «своему» исполнителю и сверх лимита, поэтому возможно «202 / 200»; возврат той же
  заявки с доработки в норму не засчитывается.

## Демонстрация и боевой запуск

Всё, что нужно только для показа, включается двумя строками в `.env` и так же убирается — код не меняется.

| | Демо-режим | Боевой запуск |
|---|---|---|
| `.env` | `COMPOSE_PROFILES=demo`, `DEMO_ENABLED=true` | обеих строк нет; `AIS_BASE_URL` — адрес настоящей АИС |
| Эмулятор АИС (`src/AisEmulator.Api`) | запускается отдельным контейнером | не запускается |
| Вкладка «Тестовый стенд», значок «демо-режим» в шапке | есть | нет |
| Адреса пульта `/api/admin/demo/*` | работают | отвечают 404 |
| Добавить / изменить сотрудника, «На перерыв» | через эмулятор АИС | нет: сотрудники приходят из АИС (`PUT /api/integration/…/executors/{id}`) |
| Сотрудники в новых и пустых отделах | заводятся сами (по 10) через эмулятор; при создании отдела — галочкой | приходят из АИС или загружаются из файла |
| Всё остальное: заявки, правила, отделы, аналитика, рейтинг, «больше нормы», загрузка сотрудников из файла, журнал | есть | есть |

Код демонстрации отделён: `Endpoints/DemoEndpoints.cs` (прокси к эмулятору), `Endpoints/GuestSandbox.cs` (свой отдел-песочница каждому гостю), `wwwroot/js/demo.js` (стенд),
проект `src/AisEmulator.Api` и `tools/loadgen.py`. Браузер обращается только к балансировщику, а тот управляет
эмулятором своим ключом — ключ АИС на страницу не попадает.

Скрипт `tools/loadgen.py` по-прежнему работает для нагрузки из консоли — через общие адреса API, то есть
с основным отделом («Банк» в новой базе).

## API интеграции

Все запросы — с заголовком `X-Api-Key`. Новые заявки и исполнители отдела — по адресу
`/api/integration/departments/{код}/…` (код отдела виден в «Настройки → Отделы»); адреса без отдела
(`/api/integration/orders`, `/executors/{id}`, `/metrics`) работают с основным отделом. Номера заявок и
исполнителей в АИС общие, поэтому статус и назначение запрашиваются без отдела.

```bash
KEY=ваш_ключ; URL=http://127.0.0.1:8080/api/integration

# исполнитель
curl -X PUT $URL/executors/1 -H "X-Api-Key: $KEY" -H "Content-Type: application/json" -d '{
  "fullName": "Иванов И. И.", "isActive": true, "dailyLimit": 40, "qualificationWeight": 1.5,
  "attributes": {"min_sum": 0, "max_sum": 5000000, "order_types": ["ORDER_1","ORDER_2"],
    "subjects": ["кредит","карты"], "segments": ["малый","средний"], "client_classes": ["обычный","VIP"]}}'

# заявка
curl -X POST $URL/orders -H "X-Api-Key: $KEY" -H "Content-Type: application/json" -d '{
  "id": 1001, "parentId": null,
  "attributes": {"sum": 250000, "order_type": "ORDER_1", "subject": "кредит",
    "client_segment": "малый", "client_class": "обычный"}}'

# почему назначен именно этот исполнитель
curl $URL/orders/1001/assignment -H "X-Api-Key: $KEY"

# смена статуса: processed | await | accept | reject
curl -X POST $URL/orders/1001/status -H "X-Api-Key: $KEY" -H "Content-Type: application/json" -d '{"status":"await"}'

# метрики дашборда для внешних систем: today | 24h | 7d | 30d
curl "$URL/metrics?period=24h" -H "X-Api-Key: $KEY"

# то же для конкретного отдела: заявка в «Логистику», метрики отдела
curl -X POST $URL/departments/logistics/orders -H "X-Api-Key: $KEY" -H "Content-Type: application/json" -d '{
  "id": 1002, "attributes": {"region": "Казань", "cargo_weight": 120, "cargo_type": "хрупкий"}}'
curl "$URL/departments/logistics/metrics?period=today" -H "X-Api-Key: $KEY"
```

В Swagger (`/swagger`) нажмите **Authorize** и вставьте ключ — «Try it out» работает для методов интеграции.

Повторная отправка той же заявки не создаёт второго назначения — в ответе `"duplicate": true`.

## ИИ-разбор заявок (необязательно)

Вкладка «Разбор заявок» считает цифры сама; ИИ по ним пишет выводы и советы: кого обучить какому навыку, где не
хватает людей, у кого много возвратов, какое правило проверить. Подходит любая модель с OpenAI-совместимым API
(`POST {адрес}/chat/completions`). Настройки — только в `.env` (он не попадает в git), после правки —
`docker compose up -d`. Без этих строк всё работает, как раньше, кнопка «Разобрать с ИИ» неактивна.

**Вариант 1 — YandexGPT Pro в Yandex AI Studio (так подключено на нашем сервере; российское облако, оплата в рублях).** В консоли Yandex Cloud: создать каталог
(его ID — `AI_PROJECT`), сервисный аккаунт с ролью `ai.languageModels.user` и **API-ключ** для него (область
действия — только модели AI Studio). В `.env` (адрес и имя модели — по документации AI Studio, раздел
«OpenAI-совместимый API»):

```
AI_BASE_URL=https://llm.api.cloud.yandex.net/v1
AI_MODEL=gpt://<ID каталога>/yandexgpt/latest
AI_PROJECT=<ID каталога>
AI_API_KEY=<секретный ключ>
```

Пошагово для сервера — [docs/DEPLOY.md](docs/DEPLOY.md), раздел 8.

**Вариант 2 — своя модель на компьютере, без облака (бесплатно, данные никуда не уходят; для запуска на ноутбуке).** Установить Ollama
(`winget install Ollama.Ollama` или [ollama.com](https://ollama.com)), разрешить ей длинные запросы и скачать модель:

```powershell
setx OLLAMA_CONTEXT_LENGTH 8192     # сводка отдела длиннее окна по умолчанию; после — перезапустить Ollama
ollama pull qwen2.5:7b              # ~5 ГБ, хорошо пишет по-русски; для слабого ноутбука — qwen2.5:3b (~2 ГБ)
ollama run qwen2.5:7b "Ответь одним словом: работает?"
```

В `.env`:

```
AI_BASE_URL=http://host.docker.internal:11434/v1
AI_MODEL=qwen2.5:7b
AI_TIMEOUT_SECONDS=300
AI_MAX_TOKENS=900
```

Без видеокарты ответ идёт минуту-три, поэтому ожидание увеличено; `AI_MAX_TOKENS` ограничивает длину ответа.

**Вариант 3 — другой провайдер с OpenAI-совместимым API:** его адрес, имя модели и ключ в тех же строках.

Безопасность ключа: он хранится только в `.env` на сервере, в браузер, журнал и логи не попадает; выдавайте
ключ сервисному аккаунту с одной ролью (только вызов моделей), поставьте лимит расходов у провайдера, не
пересылайте ключ в мессенджерах и выпустите новый после демонстрации.

- **Что уходит в модель:** только сводка по отделу за сутки — количества и доли по значениям справочников,
  очередь, доработки, справедливость, показатели сотрудников под номерами («С-1003»). Без ФИО, без текста заявок.
- **Отчёт:** находки по разделам (навыки, очередь, правила, качество, справедливость) с цифрами считает сервер,
  ИИ к каждой пишет «почему так может быть» и действия с пометкой «кому» и «что изменится»; номера сотрудников —
  ссылки на их страницы, отчёт можно скопировать или распечатать.
- **ИИ не распределяет заявки:** распределение остаётся детерминированным и объяснимым, разбор — подсказка руководителю.
- **Ответ модели** выводится только как текст; не больше двух разборов одновременно, повтор по отделу в течение
  минуты отдаёт готовый ответ; запускать разбор могут руководитель и администратор.

## Безопасность

- **Интеграция:** ключ `X-Api-Key` (сравнение за постоянное время, длина ≥ 24), лимит частоты запросов, тело до 256 КБ.
- **Вход и роли:** логин и пароль; встроенный администратор — пароль из переменной окружения, остальные
  пользователи — PBKDF2-SHA256 (600 000 итераций, соль), проверка за постоянное время и для несуществующего
  логина; cookie `HttpOnly` + `SameSite=Strict`, 5 попыток входа в минуту с адреса, входы пишутся в журнал.
  Роли (наблюдатель, руководитель, администратор) и отделы проверяются сервером на каждом запросе; блокировка
  или смена роли закрывают сессии. Изменяющие запросы конструктора требуют заголовок
  `X-Requested-With` — вторая линия защиты от CSRF.
- **Конструктор:** правила — только операторы из белого списка, без `eval` и выражений; каждое правило
  проверяется по типам параметров; изменения, которые сломали бы действующие правила или значения
  исполнителей, отклоняются (409); лимиты на количество параметров, правил и длину значений.
- **Интерфейс:** данные выводятся только через `textContent`, строгая CSP без встроенных скриптов и стилей,
  без CDN: оформление Tabler, иконки Tabler Icons и шрифт Inter лежат в проекте (открытые лицензии —
  `THIRD_PARTY_NOTICES.md`), JavaScript сторонних библиотек не используется. Выгрузка в Excel экранирует ячейки, похожие на формулы.
- **Инфраструктура:** ошибки в формате ProblemDetails без стека, заголовки безопасности, секреты только
  из переменных окружения, контейнер без root и с файловой системой только для чтения, Postgres и Redis
  не опубликованы наружу, API слушает только 127.0.0.1 (наружу — через обратный прокси с HTTPS).
